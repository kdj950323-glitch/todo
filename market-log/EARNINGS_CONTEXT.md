# 실적 임박 낙폭 종목 심층 분석 (관심종목·바닥 후보 공통 지침)

관심종목 데일리 체크와 바닥 후보 스크리너 루틴이 시작할 때 이 파일을 Read 로 읽고, 아래 규칙대로 "실적을 앞둔 낙폭 종목" 섹션을 기록에 추가한다. 이 파일을 못 읽으면 기본 지침만 따르고 최종 보고에 그 사실을 적는다. 매수·매도 추천은 하지 않는다(참고용 분석).

## 1. 대상 선별
- **낙폭 종목**: 52주 고점 대비 -20% 이하(관심종목은 표에 있는 종목 전체에서, 바닥 후보는 점수 2 이상 후보에서 고른다).
- **실적 임박**: 다음 실적 발표일이 **오늘부터 30일 이내**. 발표일은 Finviz quote 의 Earnings 칸 → 없거나 불확실하면 investing.com(https://www.investing.com/earnings-calendar/ , 종목 Earnings 페이지)로 확인. Finviz 날짜가 이미 지난 날짜(예: 10월에 'Aug 26')면 stale 이므로 쓰지 않고 `python3 market-log/tools/finviz.py earnings 티커` 로 판별한 뒤 WebSearch·investing.com 으로 다음 발표일을 다시 찾는다(ADDENDUM 섹션 M). 발표일 확인 불가면 "발표일 미확인"으로 적고 대상에서는 제외하되 본문에 사유를 남긴다.
- 두 조건을 모두 만족하는 종목이 대상이다. 관심종목이 우선, 다음은 바닥 신호 점수 높은 순. **하루 최대 10종목**(넘으면 발표가 가까운 순). 해당 종목이 없으면 "실적 임박 낙폭 종목 없음"으로 한 줄 기록한다(억지로 채우지 않음).

## 2. 종목별 분석 항목 (모두 실제로 조회 시도, 실패 시 사유 표기)
1) **이번 발표 예상**: 발표 예정일(D-며칠, 장전/장후), EPS·매출 컨센서스(조회 시점·출처 병기, investing.com 우선, 없으면 Finviz EPS est). 최근 4~8분기 서프라이즈 이력(상회/부합/하회 흐름).
2) **지난 분기 실적 결과**: 발표일, EPS·매출 실제 vs 예상(서프라이즈 %), 가이던스(상향/유지/하향 또는 없음), 시장이 주목한 포인트.
3) **어닝콜 요약**: 경영진 핵심 발언 3~5줄(수요, 마진, 가이던스, 투자·비용, 리스크 등). 어닝콜 원문/트랜스크립트 또는 신뢰할 만한 요약 기사를 WebSearch 로 찾아(예: "{종목명} Q{n} {연도} earnings call highlights/transcript") 읽고 **원문을 그대로 복사하지 말고 직접 요약**한다(문장 복사 금지, 인용은 짧게). 출처 링크를 적는다. 네이버 뉴스 API 로 한국어 해설 기사를 보조로 붙일 수 있다. 못 찾으면 그날은 "어닝콜 확인 중(미확보, 사유)"로 적고 5번 재시도 규칙에 따라 다음 실행부터 계속 다시 시도한다(그냥 넘기지 않는다).
4) **발표 이후 주가 움직임**: 발표 다음 거래일 갭/등락률과 거래량(평균 대비), 발표 후 5거래일·20거래일 수익률, 현재 가격이 발표 직전 가격 대비 어디인지(+/-%). 데이터는 Yahoo 를 쓰지 않는다(클라우드에서 차단됨). Finviz 종목 페이지는 일봉 이력을 주지 않으므로 ① 발표 다음 거래일의 등락은 뉴스 헤드라인(네이버 뉴스 API·WebSearch 의 "○○% 급등/급락" 보도)으로 확인하고 ② 발표 후 경과일에 맞춰 Finviz 의 Perf Week/Month/Quarter 와 현재가로 흐름을 근사하며 ③ 관심종목은 `market-log/state/watchlist_prices.csv`(매일 종가 누적, 2026-10-09 시작)에 해당 날짜가 있으면 그 종가로 발표 전후 5·20거래일 수익률과 '발표 직전 대비 현재 %'를 **직접 계산**한다(계산 근거 날짜를 표기) ④ 정확히 못 구하면 "근사" 또는 "확인 불가(사유)"로 적는다(추측으로 수치를 채우지 않는다).
5) **종합 해석(초보자용)**: ① 지금 주가가 많이 빠진 이유(뉴스 근거로만) ② 이번 발표에서 시장이 기대하는 것 / 부담으로 보는 것 ③ 지난 분기 반응을 봤을 때 이번에 주의할 점(예: 호실적에도 하락했는지, 가이던스에 민감했는지) ④ 체크할 포인트 2~3개. 전문용어(컨센서스, 가이던스, 어닝 서프라이즈, 어닝콜)는 처음 나올 때 괄호로 쉬운 설명을 붙인다. "사라/팔아라" 같은 지시, 수익 보장 표현, 확정적 예측 금지. 실적 발표 전후 변동성이 커질 수 있다는 한 줄 안내 포함.

## 3. 기록 형식
- 노션 날짜 토글 안에 소제목 "### 실적 앞둔 낙폭 종목 (D-30 이내)" 를 두고, 위에 요약 표(티커, 낙폭%, 발표일/D-n, EPS 예상, 매출 예상, 지난 분기 결과(상회/부합/하회), 발표 후 20일 수익률, 한 줄 포인트)를 둔다. 표 규칙은 각 루틴의 기존 표 작성 규칙(<tr>/<td> 한 줄씩, $ 이스케이프)을 따른다.
- 표 아래에 종목별 하위 토글(<details>)로 2번 항목 1)~5)를 상세히 쓴다(기본 접힘).
- GitHub 백업 마크다운에도 같은 내용을 넣는다.

## 4. 재사용·부하 관리
- 지난 분기 결과·어닝콜 요약·발표 후 주가 움직임은 분기에 한 번만 조사하면 된다. 조사한 내용은 `market-log/earnings/context/{TICKER}_{YYYYQn}.md` 로 저장하고, 같은 분기 파일이 있으면 새로 조사하지 말고 읽어서 쓴다(가격·컨센서스·D-day만 갱신). 새 분기 실적이 발표되면 새 파일을 만든다.
- 이 폴더 외 market-log/ 밖 파일은 수정하지 않는다. 커밋은 각 루틴의 기존 git 규칙을 따른다.
- 노션 "실적 발표 캘린더"(https://app.notion.com/p/337d79940ea84344b540cfd5e42d9ce3) 는 데일리 기록 루틴이 관리한다. 여기서는 읽기만 하고(발표일·컨센서스 참고) 수정하지 않는다.

## 5. 미확보 항목 재시도 (한 번 실패했다고 넘기지 않는다)
- 어닝콜 요약을 비롯해 조사 항목(컨센서스, 지난 분기 실제치, 발표 후 주가 반응 등)을 그날 확보하지 못했으면, `market-log/earnings/context/{TICKER}_{YYYYQn}.md` 에 항목별 상태를 `미확보(사유, 시도 횟수, 마지막 시도일)` 로 남기고 노션·GitHub 기록에도 "확인 중"으로 표시한다. 절대 "확인 불가"로 확정하고 끝내지 않는다.
- **다음 실행부터 매 실행마다** 이 미확보 항목을 먼저 다시 시도한다(대상 종목이 오늘의 대상 목록에서 빠졌더라도, 미확보가 남아 있는 종목은 계속 재시도 대상에 포함). 어닝콜은 보통 발표 당일 저녁~다음 날에 기사와 요약이 올라오므로 **발표 다음 날 재시도가 핵심**이다.
- 재시도 방법(순서대로):
  1. **네이버 뉴스 검색 API**(환경변수 NAVER_CLIENT_ID/SECRET, 키 출력 금지, 쿼리는 python3 urllib.parse.quote 로 UTF-8 인코딩): `https://naverapihub.apigw.ntruss.com/search/v1/news?query={q}&display=20&sort=date`. 검색어를 바꿔 여러 번 돈다: "{종목 한글명} 어닝콜", "{종목 한글명} 실적 컨퍼런스콜", "{종목 한글명} 실적 발표 가이던스", "{티커} 어닝콜", "{종목 한글명} 3분기 실적"(분기는 해당 분기로). pubDate 가 실적 발표일 이후인 기사만 고르고, 제목·요약(description)에 나온 경영진 발언·가이던스·시장 반응을 근거로 쓴다. 기사 본문 전체가 필요하면 originallink 를 WebFetch 로 열어 읽되 문장 복사는 금지, 직접 요약한다. 출처(언론사 도메인, 링크, 날짜)를 적는다.
  2. 네이버에서 부족하면 WebSearch/WebFetch 로 영어 요약·트랜스크립트 기사("{종목명} Q{n} {연도} earnings call highlights")를 찾는다.
  3. 발표 후 주가 반응·실제치가 비어 있었다면 investing.com 종목 Earnings 페이지(WebFetch)와 뉴스 헤드라인(네이버·WebSearch), Finviz Perf 값으로 채운다(Yahoo 사용 금지).
- 채워지면: 컨텍스트 파일을 `확보(출처, 확보일)` 로 갱신하고, 오늘 기록의 해당 종목 토글에 "어닝콜 요약(발표 다음 날 보강: 날짜)" 으로 내용을 쓴다. 이미 쓴 과거 날짜 토글은 수정하지 않고 오늘 토글에 보강 내용을 적으며, 가능하면 요약 표의 해당 칸에 "보강됨"을 표시한다.
- 재시도 횟수 제한: 발표 후 10거래일 동안은 매 실행 재시도. 그 뒤에도 못 찾았으면 "10거래일간 확보 못함"으로 표기하되 **주 1회는 계속 재시도**한다(새 기사가 올라올 수 있음). 재시도 시도·결과는 기록 맨 아래 "수집 로그"에 남긴다.
- 보강에 성공한 날에는 최종 보고(그리고 푸시 알림 문구)에 "○○ 어닝콜 보강 완료"를 한 줄 덧붙인다.

## 6. 관심종목 루틴 공통 의무 (2026-10-20 추가)
- **관심종목 데일리 체크 루틴**은 매 실행 관심종목 전체의 대상 거래일 종가를 `market-log/state/watchlist_prices.csv`(열: date,ticker,close)에 한 줄씩 추가한다(같은 date+ticker 중복 금지). 커밋에 `market-log/state` 를 포함한다.
- Finviz 표/JSON 파싱은 `market-log/tools/finviz.py` 를 쓴다(사용법은 파일 맨 위, 주식과 ETF 는 따로 조회). 다음 실적일이 지난 날짜면 `finviz.py earnings 티커` 로 판별해 재확인한다(ADDENDUM 섹션 M).

## 7. 바닥 반등 참고 지표 '방어 상승일' (2026-10-21 추가, 참고용 — 매수·매도 신호 아님)
- 정의: 시장(SPY)이 -0.8% 이하인 날 종목이 +2% 이상 오르고 SPY 보다 3%p 이상 더 오른 날. 최근 5거래일 안의 횟수를 센다. 배경·근거·한계는 `market-log/learning/2026-10-defense-primes-reversal.md` 와 `2026-10-financials-and-sector-cases.md` 참고(검증 표본 작고 연도별로 들쭉날쭉해 '추적할 가설' 단계).
- 계산은 스크립트로 한다(직접 계산하지 않음): `python3 market-log/tools/reversal_flags.py ...` (사용법은 파일 맨 위).
- **관심종목 데일리 체크 루틴**: 종가를 `state/watchlist_prices.csv` 에 추가한 뒤 `python3 market-log/tools/reversal_flags.py watchlist` 를 실행해, 종목 현황 표에 열 '방어 상승일(5일)'(횟수, 날짜는 메모)을 추가하고 `days_recorded` 가 5 미만이면 '누적 중(N일)' 으로 표시한다. 바닥 신호 점수 2 이상이면서 1회 이상이면 변화 목록에 '반등 초기 관찰: 방어 상승일 N회'를 한 줄 넣는다(알림 대상 아님).
- **바닥 후보 스크리너 루틴**: 후보 목록(티커, Finviz `change`, `industry`)을 JSON 으로 저장한 뒤 `python3 market-log/tools/reversal_flags.py log-candidates --date <대상 거래일> --json <파일>` 로 `state/candidate_daily.csv` 에 누적하고, `python3 market-log/tools/reversal_flags.py candidates` 로 후보별 방어 상승일과 업종 동조(`industry_cluster`, 같은 업종 3종목 이상이면 `cluster: true`)를 얻어 후보 표에 참고 열('방어 상승일(5일)', '업종 동조')로 넣는다. 기록이 쌓이기 전에는 '누적 중(N일)'. 후보 상태 파일 `state/` 변경은 같은 커밋에 포함한다(`git add market-log/state`).
- **촉매 표시**: 다음 실적이 10일 이내인 과매도 후보(RSI≤30 또는 52주 고점 대비 -15% 이하)는 표 비고에 '촉매: 실적 D-n' 을 붙인다(이번 NOC·RTX 처럼 실적이 반등을 확인해 주는 경우가 있어 참고).
- 표시 문구 고정: '참고 지표이며 매수·매도 신호가 아닙니다'. 이 값만으로 종목을 추천하지 않는다.
